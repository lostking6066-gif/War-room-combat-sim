Mode B — Video-Inspired Battle (optional, context only)

Mode A (default) is an Original Death Battle, made from the game's own profiles and combat engine. Mode B is different: paste a transcript or notes from a video you watched below. That text is shown as "Video-inspired notes" in Chapters I–II only. It does NOT grant new powers, change stats, or replace the simulation. The narration in v15 is always original — it never copies another creator's script.

Honest limit: a YouTube link alone does not let this browser file read a video's audio or captions automatically. That would require a YouTube Data API key. Use whatever transcript or notes you can actually access and paste here.

If you paste a URL but no transcript, the game will say so plainly: no video was watched and no transcript was accessed, and the battle continues in ordinary research mode. If you paste notes, claims in them are treated as user-supplied context, not verified facts, and opinions in them are not adopted as facts.

Video-inspired notes are context only. They do not add powers, forms, or stats.

Victory Rules — what counts as a win

Victory is by death (HP reaches 0), or by incapacitation lasting the rest of the fight, or by battlefield removal with no way back. The exact victory condition is stated in the results and in Chapter VI.

Regeneration can heal, but it does NOT revive after HP 0. A fighter who is knocked out stays knocked out — no dead fighter acts again, and regeneration only heals a fighter who is still alive.

No invented killing blow: if the battle hits its round cap with both fighters still alive and neither able to kill or incapacitate the other, the result is a stalemate / no-death verdict, explained in Chapter VI — not a fake finish.

Battlefield removal: removal alone does not count unless the opponent cannot return. No power in the current powersets permanently removes an opponent from the battlefield, so v15 will not claim a BFR victory it did not simulate.

WAR-ROOM AI — Four Connected Brains for 1v1 (rule-based, no paid API)

1. Combat Brain: tier scaling, counters, stamina, battlefield destruction, transformations at or below 45% HP — a street-level fighter cannot routinely hurt a cosmic foe by luck alone.
2. Character Brain: personality decisions — Batman studies first, Goku holds back to test a foe, Vegeta's pride seeks the strongest opponent, humorous fighters are unpredictable. In 1v1 there is no ally to protect, so protective shielding cannot trigger.
3. Knowledge Brain + Analysis Brain: identity, continuity, powers, feats, limits, weaknesses, transformations, relationships — plus Wikipedia + Fandom research, shown per source — and a head-to-head comparison of strength, speed, durability, abilities, experience, transformations, weaknesses and win conditions, with an explicit uncertainty note when a matchup is close.
4. Narrator Brain: turns the analysis and the recorded events into a 6-chapter episode (Contenders, Comparison, First Exchange, Turning Point, Final Clash, Verdict), using tactics and reasons, not just attack names.
Continuity check (adapted to 1v1): checks the battle before the episode is shown — a dead or incapacitated fighter must not act, powers must belong to that version, transformations must meet their trigger, and the winner must match the survivor / stalemate record.

Trade-off, stated plainly: this is a sophisticated rule system, not a language model. It can calculate, decide, and narrate from rules reliably, but it cannot write unlimited original prose like an LLM. That last step would need a local open model or a free/paid inference service, which v15 does not require.

YouTube videos cannot be read automatically by a browser file without a YouTube Data API key, and scraping YouTube is blocked. So this version does the honest version that works on a phone: one-tap YouTube searches for each selected fighter, for powers, strength, speed and transformations, plus a channel library you can grow. Canon Sources — Wikipedia + Fandom, automatically

They are more canon-specific than Wikipedia, but they are still fan sources — the game shows which source succeeded and which failed, and never claims a failed fetch was verified. Research Dossier — Pipeline Stage 1: Evidence, Not Verdict

Per fighter: source name, source type, found/not-found status, link, and fetched or cached date. Short excerpts appear ONLY here, never inside episode chapters. Demonstrated feats (from the local profile, in general terms) are kept separate from fan opinion / discussion (fan-run wikis and YouTube searches), which is discussion to investigate, not established fact, and never auto-grants a power. Conflicting versions: the game uses ONLY the selected continuity's profile and does not silently merge versions. Research is cached per fighter + continuity on this device and reused on the next encounter; use Refresh for missing or outdated info. A failed source shows ❌ honestly and the game still plays from local profiles. Research never changes battle stats — the old +10 ATK / +60 HP bonus was removed; research fills dossier fields only.

Online Storytelling Pipeline — Research → Combat → Narration → Check → Save

Stage 1 — Research Dossier: load each fighter's structured profile, then fetch Wikipedia (encyclopedia) and fan-run Fandom wiki sources automatically. Fan sources and YouTube searches are discussion to investigate, not established fact, and never auto-grant powers.
Stage 2 — Matchup Analysis: compare power, speed, dexterity, durability, stamina, tactics, transformations, weaknesses and win conditions for the selected continuities only — versions are never silently merged.
Stage 3 — Combat Simulation: our own engine decides the battle and records every exchange. The internet is evidence; the engine is the outcome.
Stage 4 — Episode: the narrator turns the battle record into 6 chapters, with Analytical, Cinematic and Reflective voices.
Stage 5 — Consistency Check: the episode is checked against the record before it is presented as verified.
Stage 6 — Saved Episode: matchup, continuities, outcome, research references and the full episode are saved on this device only, so you can re-read them.
Free storytelling, honestly: the online AI story is now the primary episode and runs automatically after every battle. The rule-based episode is the honest offline fallback, labelled as such, when the online service fails or its draft fails validation. Free services can impose quotas, change availability, or require accounts or keys — internet access alone does not provide a language model, and this game is not built around an assumed free LLM. Automatic YouTube transcript reading still needs a YouTube Data API key; the game uses YouTube search links and your pasted notes instead. Pollinations keyless requests can return HTTP 402 when its anonymous limit is reached; that is reported honestly in the fallback reason (see Technical Details), not hidden, and an optional saved Pollinations key in Advanced Settings is tried only as a secondary attempt.

Internet Connection — Properly Connected

This version connects, from the browser, to: Wikipedia, fan-run Fandom wikis, YouTube search, and — optionally — a free public AI text service (Pollinations, keyless access subject to its anonymous limits — see Advanced Settings) or your own free Gemini key. No Muse server, no paid API, and no key is sent to Muse. Your Gemini key, if you enter one, is stored only in this device's localStorage and is sent only to Google when you tap Generate.

Testing connections automatically on load — just pick fighters and play. Retest is optional, never required to play. The story-path test sends a tiny POST to the real AI service in the same format as a story request; it proves reachability only, not research accuracy or story validation.

Security note: a key in a browser game can be seen in network traffic on that device. Use a free key, never a paid/production key, and rotate it if you share the device.

Pollinations honesty note (v16.1 investigation, 2026-10-30): keyless POST and GET both answered HTTP 200 from Node when not rate-limited, but a second request inside ~30 seconds returned HTTP 402 "Free limit reached: 1 reply every 30 seconds per IP". So a 402 in this game usually means the free anonymous limit was hit, not that keyless access is permanently gone — the fallback reason now says so plainly. If no key is saved, the game never asks for one in the main flow: the honestly labelled offline episode is the result. Live-browser AI generation is still unproven and is not claimed here.
